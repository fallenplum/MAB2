# 条件 relay 通道漂移诊断结果

## 结果摘要

该阶段在四个冻结 M60 面板上执行了离线 synthetic replay，每个场景包含 2304 个题目×团队单元。变换只改变 relay 概率分布列，保持四行接口和 terminal label 矩阵不变。

| 场景 | stale error | source-only CTDR error | TCR guard error | TCR tokens | cold tokens |
| --- | ---: | ---: | ---: | ---: | ---: |
| 强度 0.25，四行 | 0.0647 | 0.0321 | 0 | 759.34 | 601.90 |
| 强度 0.50，四行 | 0.0681 | 0.0443 | 0 | 777.90 | 616.67 |
| 强度 1.00，四行 | 0.0690 | 0.0764 | 0 | 790.22 | 611.12 |
| 强度 1.00，单行 | 0.0543 | 0.0191 | 0 | 271.67 | 531.43 |
| 强度 1.00，双行 | 0.0582 | 0.0395 | 0 | 441.87 | 556.68 |

四个不同单行位置的强度 1.0 重放中，TCR guard 均保持 exact set 1.0，token 为 265.82–277.81，冷重启为 514.89–526.55。单行稀疏变化的 token 节省约 47%–50%。双行变化仍保持 exact set 1.0，token 节省约 20.6%。

## 机制解释

当前 source-only radius 在 relay 条件变化时不能保证旧证书有效。错误来自旧 relay 向量被当成新图条件核，source reweighting 无法覆盖这一变化。TCR guard 通过重查变化行恢复了 exact decision set。所有四行都变化时，重查行与复用旧 terminal 观测的策略比冷重启更贵，说明条件感知机制需要根据变化范围选择局部重查或冷重启。

## 证据边界

这些结果是固定 worker 输出上的预先指定 synthetic transform。它们支持接口级失效机制和局部重查的可行性，不能证明真实模型在图编辑后会产生相同条件分布变化，也不能替代新模型推理的独立确认。下一轮应在真实图编辑 prompt 上获取新 relay 行，并固定 changed-row 检测协议。
