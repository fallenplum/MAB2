# MAB2 E0-R1 离线修复报告

## 状态

本轮状态为 **`R1_VALID_REPLAY_DEVELOPMENT_ONLY`**。本轮只使用已有 E0 轨迹、官方已下载的本地标注文件和 CPU 离线代码；新增 GPU 时间为 0，付费 API 成本为 0，未下载模型或扩展数据，也没有自动进入 R2/E1。

R1 的目标是修复评测口径并判断旧结论哪些仍可用，不是把开发数据改写成独立测试集。原始 E0 JSON 保留不动；由于顶层 Windows 路径字段未正确转义，R1 只生成了序列化修复副本，并在 `RAW_TRACE_SERIALIZATION_REPAIR.json` 中保存源文件和副本 SHA-256。

## 关键修复结果

旧 strict 结果使用了查询前缀长度作为分母，导致每组实际上以 `n=1` 证书运行。R1 对每个有效组固定使用完整事实数 `n`，未查询事实保持 `unknown`，仅在证书安全时停止。80% 阈值的 30 个有效组共需 472 次查询、581,101 input tokens 和 1,383 output tokens；动作是 29 个 FAIL、1 个 PASS，相对冻结 human target 为 7/30 动作错误。旧的 30 次查询、17/30 错误结果已标记为无效历史路径，不能继续作为基线。

32 个预注册组中 30 个有新冷事件，2 个没有事件，后者进入无效分母并未被补数据。人类目标为 6 个 PASS、24 个 FAIL。

除 80% 主阈值外，其余阈值仅作敏感性诊断；不能把较低动作错误直接解释为更好的评测，因为 human target 本身按 80% 规则构造。

## 强基线和成本诊断

在相同 30 个有效组、完整事实数和 input+output 加和 token 口径下，冷启动总成本为 1,262,853。随机顺序 100 个种子/组的无放回精确期望为 503,239.86 token，即相对冷启动节省 60.15%；clairvoyant witness 下界为 314,416 token，即 75.10%。这两项是平坦可加 token 成本下的离线诊断，不是在线可部署算法收益，也不是新模型实验。

实际 3,000 条随机回放的平均值为 13.493 次查询、16,697.77 token；相对冻结 human target 的动作差异为 700/3,000，原因是 30 个事件证书动作中有 7 个与 human target 不同。随机和 clairvoyant 结果不能替代真实服务延迟、检索费用或模型调用账单；这些字段在历史轨迹中不可核验。

## 缓存、图和 Flat 诊断

- 使用冻结官方事实文本在 scorer 侧构造 `(group_id, fact_index, fact_digest)` occurrence key，旧事件 777/777、新冷事件 1,073/1,073 与 digest 完全匹配。该映射不读取标签，只解决事实身份问题。
- 70 次 raw 文本重合和 71 次 canonical 文本重合只能标为 `TEXT_MATCH_ONLY`/`CANONICAL_DIAGNOSTIC_ONLY`。由于历史执行合同、证据 ID、计费和在线缓存权限不可独立验证，认证缓存命中数仍为 0，不能把 Warm 或 Stale 当作严格公平基线。
- 轨迹中的 10 个 `None` 是 verifier 输出未知，不是 human gold 缺失；30 个有效组均有可用的后置 human target。固定 n 证书中的其余 `unknown` 还包括尚未查询的事实，二者在结果中分开处理。
- InstructGPT 到 ChatGPT 是整篇文档更新；30 个有效组中 28 个事实数不同，因此不能按局部事实编辑解释。
- 当前轨迹是主题级 fan-out 和逐事实 verifier，没有可核验的动态共享祖先；`NO_BUNDLE_STRUCTURE` 仍成立。
- Flat 原始输出的 30 条可见结果均不是严格 `PASS`/`FAIL`，另有 2 条为空。严格 parser 的有效率为 0/30，旧 substring 解析得到的单个误判也不能作为结果。因此 Flat 只能标为 `INVALID_BASELINE/PARSE_DIAGNOSTIC_UNFAIR_FLAT`。

## 可靠性检查和限制

`n=33` 边界、`n=1..8` 全部三值标签穷举、Fact/Document parser 分离、随机期望数学和突变测试均通过，单元测试为 4/4，突变测试为 6/6。测试没有使用 sealed test，也没有为置信区间运行 bootstrap；项目约定从 2026-11-14 起不计算和不报告置信区间。

E0-R1 AuditKit 未在工作区找到，记为 `EXTERNAL_REFERENCE_MISSING`。旧 E0 报告的早期阻塞段落、`WORKFLOW_GRAPH.json` 和后续执行日志之间存在状态漂移；R1 以实际 raw trace、manifest 和可重放代码为事实来源，并保留冲突记录，不覆盖旧文件。

## 结论和后续边界

R1 证明了旧 strict gate 的前缀 `n` 是实质性评测错误，也证明 Flat 基线和严格 cache 结论目前都没有合法的公平比较资格。修复后的 80% 证书仍有 7/30 human-target 动作错误；随机和 clairvoyant 的节省只说明平坦离线诊断存在 headroom，不能支撑图结构方法、缓存复用或端到端服务收益主张。

因此本轮不宣称 ACL 结果，不自动进入 R2/E1，也不把 60.15%/75.10% 写成可部署算法提升。若要继续，下一阶段必须先提供可验证的 cache permission contract 和合法 post-edit trace，再重新执行匹配基线；否则应继续保留当前负结果。
