# Closure revalidation: reproducibility entry point

The inference operator, scientific design, selection rules, evaluation, and resource caps were frozen before formal generation. Reporting and independent auditors were added while formal outcomes remained closed. These checks do not change the nominee or acceptance gates.

## Public CPU checks

From the repository root, using Python 3.11 and NumPy:

```console
python -B experiments/cycle2_20261113/closure_revalidation_v1/build_portable_closure_bundle.py --output /path/to/new/code_bundle
cd /path/to/new/code_bundle
python -B run_artificial_checks.py
```

Use a previously nonexistent output directory. The exporter verifies every execution/scientific source pin, preserves source bytes, and builds the flat import layout used by the server. It copies code and artificial fixtures only. The 36 explicit checks cover operator context access, live-node execution, shared model allocation, no hidden service inputs, paid feedback, budget enforcement, no silent failures, policy/cost reconstruction, and raw answer scoring. No model is loaded or generated by these tests. This is a tested package layout, not a new scientific reproduction.

`render_closure_report.py` additionally needs matplotlib. Selection/extraction needs PyArrow and the licensed HotpotQA train files. Exact server tokenization/replay requires the qualified tokenizer versions; the local analysis environment is not a substitute.

## Frozen model execution

The qualified environment is Python 3.11.9, torch 2.9.1+cu128, transformers 4.54.0 and tokenizers 0.21.4. Models are Qwen2.5-3B-Instruct and Mistral-7B-Instruct-v0.3, in BF16 with eager attention. Model/config/tokenizer hashes are retained in the private frozen plan; the public execution and scientific contracts pin source hashes. Do not silently upgrade an identity, patch a frozen operator, or replace weights to make identity checks pass.

With authorized local model weights, frozen question payloads, selection manifest, and a separately approved resource plan on Linux:

```console
python -B closure_runtime_v2.py --plan /private/new_plan.json --plan-sha SHA256_OF_NEW_PLAN
```

The plan specifies output path, source pins, qualified identities, data hashes, generation seeds, physical GPU placement, assignments, and conservative residence caps. Relocating paths requires a new provenance plan and new output directory; never overwrite the original frozen plan or archived run. A new model execution consumes real GPU budget. This README is not admission for a sixth candidate or an unbudgeted rerun.

The three-source aggregation baseline has two Qwen sources, one Mistral source, and a Qwen aggregator. It is four calls, not three homogeneous Qwen calls. Three-Qwen voting is a different, cheaper baseline.

## Archive, scoring, and audits

The exact sequence is: all worker exits and actual residence closure; complete archive manifest and per-file hash verification; CPU exact request replay using recorded generations; fixed selected-train label extraction; frozen I/C/S scoring; independent arithmetic/cost reconstruction; independent raw-answer and voting reconstruction; aggregate report and figure review. Label/scoring CLIs require hash-pinned approval records, complete coverage, and successful replay. They fail closed for partial archives. The following last-stage commands operate only on already approved and scored private artifacts:

```console
python -B audit_closure_raw_scoring.py --approval /private/SCORING_APPROVAL.json --private /private/scoring_001/PRIVATE_REPLAY.json --summary /private/scoring_001/SUMMARY.json --output /private/RAW_SCORING_AUDIT.json
python -B render_closure_report.py --summary /private/scoring_001/SUMMARY.json --private /private/scoring_001/PRIVATE_REPLAY.json --audit /private/INDEPENDENT_POINT_AUDIT.json --cost /private/ROOT_COST_CLOSURE.json --output /path/to/new/aggregate_report
```

`audit_closure_independent.py --help` describes the required private and summary hashes. CPU replay verifies the recorded execution but does not regenerate model samples. The separately written scorers are agent-implemented checks, not human independent peer review. Hardware/library changes can affect stochastic generation despite fixed seeds.

## Data and information boundaries

Only HotpotQA distractor train is used, pinned to dataset revision `1908d6afbbead072334abe2965f91bd2709910ab`. Official validation/test remains unopened. The full recorded question-exposure union is excluded before the first 640 capacity-eligible entries are selected. I8/C8/S64 episodes are disjoint. Once scored, all 640 questions become exposed development data and cannot be recycled as independent confirmation.

Question text, reference answers, IDs, exposure lists, per-question matrices, raw journals, weights, machine addresses and credentials stay private. Thus the public repository alone supports code/artificial checks and aggregate-report inspection; it does not claim unrestricted exact regeneration of the original private selection. The project owner retains the manifest-linked private bundle under the project root. Licensed data plus the authorized private selection and archive are needed for identical full replay. Public tables retain episode/seed aggregates, paired differences, correction/breakage counts, and stage/model costs.

No new confidence intervals or bootstrap runs are computed. A common complete-token cap is not equal actual spending. Token utility is a declared tradeoff, not monetary cost; scoring-oracle human cost and historical unmeasured occupancy remain unknown. All negative decisions and implementation incidents are retained. The final project scientific status must be read from the completed scientific closure, not inferred from this README, a checkpoint, or passed artificial tests.
