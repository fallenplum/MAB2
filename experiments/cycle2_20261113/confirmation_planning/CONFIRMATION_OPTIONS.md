# 独立确认的统计与全账预算选项

状态：**OPTIONS_DRAFT；尚未冻结最终确认样本量、主检验或 GPU 配额。** 本工具读取零份真实 R1 I/C/S 数组、零份官方 test 原始文件。数字均为显式参数假设计算；不是已观测效应、实际功效或吞吐报告。官方数据卡查询出现一个公开示例的意外展开，已单独私有记录内容哈希并交 split owner 定位排除；因此不能宣称本子任务完全未见任何题目文本。父控制器已用纯元数据定位为历史 train/online_stream，且不在当前 R1 选择中；未来确认必须读取附加排除清单。该示例未用于方法设计，不改 R1 已冻结实验，也不减少官方 test 的元数据上界。

## 1. 要确认什么

R1 有 8 个学习 episode，每个独立 I12/C12/S24；服务合计 192 个不同题目。同一道服务题在 A（no_change）与 B（change）上配对，不能把两个背景当成 384 道独立题。8 个 episode 同时绑定预定图变换与 seed；它们不是 8 个独立数据集，也不能分别识别图配置效应与 seed 效应。

| 目标量 | 需要的随机化/样本层级 | 能支持的表述 | 不能支持的表述 |
| --- | --- | --- | --- |
| 固定已学策略、固定模型与图配置混合的条件服务效应 | 在策略冻结后取得独立服务题；方法在同题、同 seed、同背景配对 | 这些冻结策略在指定任务分布/固定图混合的平均收益 | 换一批初始化/反馈银行重新学习仍稳定改进 |
| 整个学习算法的无条件效应 | 多份独立 I/C 银行、预定学习随机数、独立 S；银行/episode 是外层单位 | 对预先定义银行采样及图混合重新学习后的期望收益 | 仅用同一银行跑多个推理 seed 就证实重新学习稳定性 |
| 图变化交互效应 | 同题比较 `(candidate-baseline)_B - (candidate-baseline)_A`，保留 A/B 协方差 | 背景变化是否改变方法间收益 | 将 A/B 当独立组检验，或只看 B 显著、A 不显著就宣称交互显著 |
| 两个任务上的有限集合效应 | 分任务报告；预先固定等权 macro 或明确每任务都需通过 | 这两个指定任务上的表现与异质性 | 2 个任务代表广泛任务总体；5 个 seed 变成 10 个独立数据集 |

若完整评估一个固定的有限 benchmark、全部固定 seeds 和冻结策略，其均值是该有限对象的精确描述。置信区间额外依赖将题目/seed/银行视为某种总体样本的假设，不能把 bootstrap 当作凭空创造新样本。固定 balanced graph grid 的推断范围也只是该预定混合，除非另外定义并采样图总体。

## 2. 透明的功效/精度计算

对单个固定策略比较，令 `D=Ycandidate-Ybaseline ∈ {-1,0,1}`，`δ=E[D]`，`d=P(D≠0)`。则 `v=d-δ²`，且必须满足 `|δ|≤d≤1`。独立配对题目近似 `SE=sqrt(v/N)`。工具使用双侧正态临界值和 `P(|Z+δ/SE|>z_(1-α/2))` 计算假设功效；默认 α=.05。它不是精确 McNemar 功效，也未考虑小 cluster、模型选择或多重比较。

NIST 的 McNemar 文档明确要求配对之间独立；稀少 discordant pairs 需考虑离散二项方法。不能把基于 episode 共享策略的相关题目，或 exact-uniform 的非二元期望成绩，直接送进普通 McNemar。[NIST，Description/assumptions/test statistic](https://itl.nist.gov/div898/software/dataplot/refman1/auxillar/mcnemar.htm)。**本表的 binary discordance 只适用于两边均为实际二元回答的单策略配对。R1 uniform exact expectation 是多个动作质量的加权平均，其差值一般连续在 [-1,1]；正式设计应使用预先估计/假设的实际 paired-difference variance 或模拟，而不能伪称它有 binary discordance。** 工具的 `normal_summary(effect, mean_variance)` 可直接承接这种已声明方差。

以下均忽略学习层波动，只展示条件独立配对的理想近似：

| δ（百分点） | 假设 d=.10 达 80% 功效所需 N | 假设 d=.20 达 80% 功效所需 N |
| --- | ---: | ---: |
| 1 | 7,842 | 15,690 |
| 2 | 1,955 | 3,917 |
| 3 | 865 | 1,737 |
| 5 | 307 | 621 |

在 δ=.02,d=.10 时，N192 的近似 95% 半宽为 4.46 个百分点、功效 .142；N1319 半宽 1.70 个百分点、功效 .634。在 d=.20 时，N1319 半宽 2.41 个百分点、功效 .369。**这些是模型假设下的计算概率，不能说项目成功概率为这些数值。** 两任务 Bonferroni/Holm 等确认家族会进一步改变门槛，以上尚未校正。

### 学习 episode 的方差下限

设随机学习银行带来的 episode 真效应方差为 `τ²`，总单题边际方差为 `v`；独立 E 个 episode、每个 m 题时：

`Var(grand mean)=τ²/E + (v-τ²)/(E*m)`。

这是显式矩假设，要求 `0≤τ²≤v`，不同 episode 银行独立且抽样分布符合目标；真实图异质性/seed/银行混杂未必满足同分布。固定 E 时，增加 m 无法消除 `τ²/E`。不要再把完整 v 加到 within 项，否则重复计算。

在 E8、m24、δ=.02、d=.10 下：

| 假设 episode 真效应 SD | 正态 95% 半宽（百分点） | 与相同方差 iid 题目等效数量（仅模型诊断） |
| --- | ---: | ---: |
| 0 | 4.46 | 192.0 |
| .05 | 5.61 | 121.7 |
| .10 | 8.12 | 58.0 |

8 个 cluster 的 percentile bootstrap 不提供自动可靠的覆盖保证。正式无条件确认需增加独立银行/episode，并在模拟数据上按最终采样/分层/缺失规则检验分析程序；若资源不够，应收缩为条件策略结果，而不是以更多同 episode 服务题冒充更多独立学习。

### 至少 5 seeds 怎么使用

每个 task 使用预先固定不少于 5 seeds，可减少“只挑一个随机数”的风险；它不是统计充分性保证。所有方法共享 seed 和题目形成配对。报告每 seed 和聚合结果；不挑最佳 seed，不把 N×5 行当独立题。

对于同一 N 题×S seeds 的交叉设计，工具给出假设分量：

`Var(mean)=σ_question²/N + σ_seed²/S + σ_residual²/(N*S)`。

三项和等于声明的单对 marginal variance。若波动完全来自题目，S=1 改成 5 不增加独立题目信息；若有全局 seed/学习策略效应，N 增加仍保留 `σ_seed²/S` 下限。只在 residual 独立这一理想端点下才有 1/(N*S) 缩减。5 个 seed 难以稳定估计 seed 方差；可把 seed 固定，明确报告条件于这组 seed 的题目效应，再用逐 seed 分解展示稳健性。若声称对随机重学过程泛化，必须另有独立银行，不能只换 decode seed。

关于单数据集样本、重采样与跨数据集单位的区分，见 [Demšar 2006 §3，p5](https://jmlr.org/papers/volume7/demsar06a/demsar06a.pdf)。交叉随机因素会产生单纯增加一个维度仍不能突破的功效限制，见 [Westfall/Kenny/Judd 2014，作者摘要](https://pubmed.ncbi.nlm.nih.gov/25111580/)；本次只读其 metadata/abstract，没有声称读完全文或将其心理学设计直接复用为本项目保证。

官方 GSM8K 数据卡 YAML 的 main train=7,473、test=1,319；socratic 是同一题目集合的另一答案形式，不能增加独立样本容量。[官方数据卡](https://huggingface.co/datasets/openai/gsm8k/blob/main/README.md)。1,319 是上限，不是当前已经验收的净封存题数。公开模型预训练是否含 benchmark 与项目内部未接触是两个问题；后者审核不能证明前者不存在。

## 4. 与 160 GPUh 全账连接

全额 160 GPUh 不是每候选额度。可新承诺额 = `160 - settled_actual - unsettled_run_reserve - other_committed_reserve`，三类必须互斥且覆盖资格、失败、重试/恢复、模型加载、自有任务全部卡时间；不能拿总 walltime 除以 8，也不能遗忘未结算运行。最多 5 轮正式候选仍是独立上限，父控制器同时核验。此工具没有最新已结算快照，`current_budget_snapshot=null`，因此没有声称当前还剩多少小时。

实际 GPUh 最终取完整 worker 时间账本；每 call 均值只供预估。应从不含最终 test 的 qualification/dev 实测不同阶段/长度/缓存形态的吞吐，并用保守上界规划。多卡共享需父控制器查真实进程与吞吐；显存空闲不是吞吐保证。抢占/共享拖慢产生的任务驻留时间也须按项目合同计账。

对已资格验证的 R1 特定 9 节点/6 toggles 几何：

- cold 单图=9 calls；它只覆盖一个策略动作，不自动覆盖强 baseline。
- 单背景完整 7-action 菜单=9+6×2=21 calls；A/B 两背景完整菜单 exact union=37 calls。这两个数字不能推广到未验收模型/执行器/图变换。
- 一个 I12/C12 学习 episode（完整 A 与 A/B 菜单物理收集）为 12×21+12×37=696 calls。新方法若不采全菜单，必须单独锁定请求并实测，不能继续套该值。
- 相同题、同 seed、同模型和执行状态下所有方法共享 exact cache。uniform exact expectation 要计算所有实际支持动作的加权结果，不能偷偷抽一个副本或挑最好动作；只有可证明相同图/执行状态才可复用。
- **物理采集账本**计算预收集菜单/共享缓存实际运行；**逻辑部署账本**对每方法计初始化+反馈+未来服务，不能把缓存预收集免费赠给某方法，也不能把上限当成实际开销。质量必须与完整成本一起确认。

假设两任务，每任务 5 个学习银行/5 seeds，每任务 N 道服务题各过 5 seeds，A/B完整菜单37calls、每学习银行696calls；额外假设固定1 GPUh+15%失败预留。以下仅为成本算术：

| 每任务独立服务题 N | 假设 .25 GPU秒/call | 假设 1 GPU秒/call |
| --- | ---: | ---: |
| 192 | 7.38 GPUh | 26.07 GPUh |
| 400 | 13.53 GPUh | 50.65 GPUh |
| 1,319 | 40.68 GPUh | 159.27 GPUh |

这里的 .25/1 秒、1小时、15% 全为规划假设，**没有实测依据**。1,319/任务行也不证明第二任务有该净容量。成本网格另含4/10秒：吞吐变化足以让同设计完全不可行。`calls_per_learning_replicate=696` 的5份银行不含 graph-configuration全面交叉；若要每图配置×5独立银行，应增大学习replicates及服务调用，并用对应统计单位计算，不能借5个数字覆盖整个随机因素。

## 5. 父控制器可自动选择的三类选项

| 选项 | 何时使用 | 优势 | 劣势/可声明范围 |
| --- | --- | --- | --- |
| A：固定策略的独立服务确认 | 开发证据已选择冻结方法；学习重复预算紧 | 多数预算用于独立题；最清晰的同题 paired comparison | 只确认固定银行/图/seed mixture，不能宣称重新学习算法普遍有效 |
| B：两任务×≥5学习 seeds/独立银行的外层重复 | 方法机制成立且资源允许银行重复 | 直接暴露学习与随机数不稳定；可报告任务异质性 | 5个外层重复仍少；需新独立银行和正确crossed分析；不能伪装10个datasets |
| C：暂不打开最终 test，补独立开发或降级为负结果/机制论文 | 最小科学效应在净容量或预算下没有可用精度；创新/公平baseline未就绪 | 保留封存 test；不靠挑结果扩大主张 | 无法交付“已独立确认的ACL正结果”；需诚实报告有限范围 |

建议次序：**先固定科学上有意义的效应/精度和最终主张，再用开发数据估计 paired variance/episode variability 的保守区间，最后用全账和净数据容量选择 A/B/C。** 开发效应小而噪声大时不要把点估计当真实效应；透明报告范围，不从本表反选最有利参数。尚未选择任何选项。

主检验建议冻结一个 candidate-vs最强同预算 baseline 的主要对比；其他消融为预定次要家族并校正。若主张“两任务均改善”，预定 intersection-union 逻辑并要求各自方向/门槛成立；若声称各任务独立发现或允许任选其一成功，则需预定 familywise 控制。macro 改善不等于每任务改善。测试失败后保留全部结果；改方法后的新实验必须重新标为开发并保留未用确认集，不能反复查询同一 final test。

## 6. 工具与验收边界

- `confirmation_calculator.py`：纯 stdlib CPU 数值计算，无网络、实验路径、结果读取或 GPU 调用。
- `ASSUMPTION_GRID.json`：220 行假设情景，包含 effect、discordance、E/m/episode SD、crossed variance shares 和吞吐假设；固定观察标记为 false。
- `test_confirmation_calculator.py`：29 项合成检查；`SYNTHETIC_TEST_RECEIPT_001.json` 记录源码 SHA。测试验证算术/守卫，不证明统计假设或小样本覆盖率。
- `SOURCES.json`/`SEARCH_LOG.json`：当前实际阅读范围；无“全文精读”或 Google 成功查询的虚构声明。
- `private/`：仅内部数据暴露处理，禁止公开；非论文案例数据。

运行：`python confirmation_calculator.py --output NEW_ASSUMPTION_GRID.json`；拒绝覆盖。测试：`python test_confirmation_calculator.py --receipt NEW_TEST_RECEIPT.json`。`budget(...)`/`role_capacity(...)`/`validate_role_hashes(...)` 供父控制器按已经核实的元数据调用，不承担 source-exposure 完整性验收。

**置信度：** 代数与合成算术核验高；将假设网格适用于真实 R1/R2 分布为低，因本子任务没有看实测 paired variance/学习方差；最终确认可行性尚未判定，等待净数据容量与全账/吞吐。这不是停止项目的判决，也不是批准启动确认。
