## G2题外条件信用预测

### 科学问题与设计

预测目标为同一题与相同其他边状态下，将边e从0设为1产生的期望最终质量差。每个种子内的两个图共享节点随机流，预测器在heldout标签揭示前输出图质量预测之差。

仅使用原400道校准题，按题划分为训练200、调参80、heldout120。划分、锚图和翻转由题目ID及不同SHA域预抽。G1的200道动机题及标签继续独立保管，官方GSM8K测试集保持封存。

每题有两个独立锚图，分别来自p=.25与p=.75的Bernoulli图分布。每个锚图执行基图及全部12个单边翻转，使用5个独立节点种子。重复mask经别名表引用同一执行和质量记录。实际计划为51,970个图与种子输出，形成9,600个题目、锚图与边的信用坐标。

控制变量为原冻结3B模型、4个固定工作角色、固定汇总器、2轮执行、消息上限、解码设置、节点随机流、评分器和闭包缓存语义。两个图密度family与全部12边在指标中等权。

### 预测器与标签使用

题目表示采用冻结MiniLM、仅训练200题拟合的PCA8和常数维。二阶图模型共711维，一阶图模型共117维，二者共享表示、原始质量表、题权和8项ridge正则网格。每个唯一题目与图聚合5种子质量均值，在模型F的训练表中只加入一次，每题训练总权重为1。

| 方法 | 训练与作用 |
|---|---|
| B0无条件边均值 | 在训练200题、两个锚图和5种子的有向信用差上，逐边求等权均值 |
| 一阶模型M1 | 用相同题目表示与单边图特征拟合F，检验随题变化的信用预测 |
| 二阶模型M2 | 在M1基础上加入边对特征，检验对其他边状态的建模 |
| 零信用预测 | 提供稀疏场景的描述性误差参照 |

各模型分别用调参80题的题均权paired credit MSE选择alpha，平手时取较大alpha。选中模型保留训练200题的拟合与原PCA。全部heldout预测、模型和来源冻结后，独立评估器获得heldout120题标签。首次标签访问事件保存独立时间记录与此前冻结哈希。

### 主要指标与阶段门

主指标为heldout题上B0风险减M2风险的配对差。每题先对两个锚图和12条边等权平均，再对120题平均。同一带噪声信用目标上的方法差抵消平方噪声的加性偏置。绝对风险另用跨独立种子的交叉乘积无偏估计，保留负估计。

主区间采用10,000次整题paired bootstrap，seed固定为39173。完整执行、数据隔离和独立重放通过，且主风险差95%区间下界严格大于0时，判定G2主门通过。

M1风险减M2风险另行完整报告。**若G2相对B0通过，而二阶模型相对一阶模型未取得支持正收益的区间，结果归因为相对于无条件边均值的预测改进。** 其他边状态带来的额外价值仍需对应比较的证据。后续策略采用何种预测器及其理由，在G3前明确冻结。

补充报告全部24个family与边组合的支持、风险差、正负题贡献、零预测误差，以及观测到5种子信用差全零与出现非零差两类坐标的误差。主指标持续覆盖全部预定坐标。

### 预算、交付与风险

正式生成调用上界为124,000次，基于每个题目与种子至多62次新物理调用。8张候选GPU的资格调用各至多89次，工程上界共712次，单独记账。正式计划去重输出数为51,970，原设计输出上界为52,000。失败、孤立调用、评分和任何未知在途成本进入各自账本。

交付包括冻结计划与来源、特征及秩审计、全局输出冻结、模型和预测冻结、独立评分与统计重放、完整成本汇总，以及全部模型与family的正负结果。

优势在于题级隔离、均衡边覆盖、同质量来源对照和配对风险差。风险来自稀疏信号、200训练题对711维模型的正则化需求、120题heldout的有限精度、编码截断，以及两个图密度分布的适用范围。G2结果与成本将共同决定G3的规模和预算合同。

## G3完整同预算下的机制实验

### 科学问题与共同条件

检验图改变后，使用条件信用和预算化复检来选择新证据，能否在完整成本约束下提高在线服务质量。

全部方法使用相同问题流、原模型与角色、汇总器、消息协议、候选边空间、闭包执行器、初始可用证据及反馈权限。当前题的服务答案在质量揭示前冻结，反馈仅影响后续题。历史图质量标签持续保留原图身份，每个质量标签对应一次合法更新。

正式实验至少使用5个预先列明的独立题流种子。每个种子下，各方法面对相同的题目顺序、环境变化和基础随机流。适应过程中的相邻题保持其时间依赖，推断以独立题流重复为主要单位，逐流结果全部呈现。

### 完整机制对照

候选完整机制与以下对照共同运行。每个差异均落实为明确的决策规则，其余系统与反馈条件保持一致。

| 对照 | 要隔离的机制 |
|---|---|
| 静态信用 | 初始化后不购买信用更新，检验持续复检的价值 |
| 随机复检 | 用预冻结随机规则选择复检对象，检验选择性的价值 |
| 周期复检 | 按预冻结间隔审计，检验自适应时机的价值 |
| 时间陈旧度 | 依据距离上次审计的时间或题数选择，检验图条件信息的价值 |
| 仅不确定性 | 仅使用预声明的预测不确定性分数，检验图变化权重的价值 |
| 去除图变化权重 | 保留其余采集公式，隔离图改变后的目标重加权 |
| 忽略重执行成本 | 采集决策使用忽略闭包新增成本的规则，实际支出仍按统一账本和预算停止 |
| 禁止恢复 | 将已移除边排除于恢复动作，检验恢复能力 |
| 多题单图标签 | 为每题仅提供预声明单图质量反馈，隔离同题反事实标签结构的价值 |

多题单图对照与同题多图方法使用同一完整费用上限，分别呈现可见标签数量、问题覆盖与计算支出。全部对照保留失败和阶段损失。

### G3开始前必须冻结的数值

下列数值依据G2实测调用、token、评分和运行开销确定，并在任何G3题流开始前冻结。

- 质量与服务成本权衡系数λ及其成本单位。
- 审计token总预算、初始证据预算、探索份额和正常服务的预留规则。
- 正式流长度、至少5个题流种子、问题顺序和环境切换方案。
- 公共预算网格、主要预算点、主要机制对照和多重比较规则。
- 周期间隔、陈旧度规则、不确定性定义、恢复阈值和各对照的必要参数。
- 开销摊销的服务长度、共享初始化规则及超预算停止行为。

开发选择使用预声明数据范围和相同搜索权限。初始证据取得的成本与可见信息逐方法记录。正常服务预留不足时停止追加复检，保留其余服务与失败状态。

### 主要指标、曲线与阶段门

建议主指标为预声明共同预算点下、相同流长度上的最终服务质量差，主要对照预先指定为静态信用。跨流按配对重复汇总，并预先固定区间和判定规则。质量差下界满足冻结阈值、完整预算合规且反馈隔离通过时，G3主门通过。其他机制比较按预声明规则报告。

同时交付质量对累计完整token成本的轨迹、公共预算网格上的质量与成本点、逐流结果、复检次数、边恢复行为及校准开销的摊销曲线。累计轨迹标明已服务题数，共同预算比较保持相同正式流长度。

完整token账本覆盖实际服务、初始化、探索、反事实重执行、失败和模型式评分调用。规则评分记录次数与CPU开销，任何折入统一预算的换算在G3前固定。物理调用以唯一call ID结算，缓存复用继承原费用来源。探索用途与反事实执行可有交集，交集单列，合计按物理记录去重。

同时报告开发总投入、各方法部署初始化、在线增量与每服务题摊销开销。G1动机数据持续排除于在线预测器的可用标签集合。共享GPU上的墙钟和CUDA事件时间记录实际竞争条件，正式速度结论需要一致的设备与调度条件。

### 交付、优势与风险

交付包括G3预注册配置、逐流质量与完整成本汇总、全部对照、采集与恢复轨迹、标签更新审计、失败账本和配对统计。

优势在于同预算控制和机制拆解，可分别观察信用更新、时机、图变化权重、重执行成本及恢复能力。风险在于适应流的时间依赖、少量独立流的区间精度、预测误差与采集偏差的相互作用，以及初始化费用对短流结果的影响。5个流是最低重复要求，最终重复规模与统计规则在运行前依据开发证据决定。

## G4多任务、近邻与完整验证

### 第二任务的数据与评分审计

最低任务组合为GSM8K与BBH。BBH先核对官方数据版本、题型、答案语法、任务标识、提示示例、scorer与可用划分，再建立相互隔离的开发、校准、流和封存评估清单。官方材料分别提供任务数据和提示，具体划分方案需在本项目使用前审计固定。[BBH官方仓库](https://github.com/suzgunmirac/BIG-Bench-Hard)

BBH按题型核对数值、选项、布尔或字符串答案的评分规则，保留格式错误与歧义输出的处理。提示示例与开发题的重合、任务文件间的重合和跨split重复均进入数据审计。

任务内题目留出支持题外泛化。跨task泛化需要整项任务留出，并让该任务的标签、提示选择和超参数保持在开发流程之外。两类协议分别命名、分别报告。GSM8K官方test继续封存，BBH的封存范围和来源身份另行明确。

HotpotQA作为后续扩展，先锁定提供的证据与检索协议，再评估多跳设置中的图信用。扩展优先级依据前述阶段的证据和成本决定。

### 直接近邻与系统参照

至少完成两项直接近邻的受控复现，优先审计AgentPrune与AgentDropout，并保留SafeSieve、E2-Explainer等候选的来源与能力登记。逐项记录官方paper、代码commit、许可证、动作空间、训练标签、反馈权限、汇总方法和完整预算。

每项近邻分别说明官方原版可执行能力与本系统适配后的能力。固定4节点、2轮、12候选边合同下的适配对照，与其原版能力结果分别标识。受控版本需明确哪些参数、角色、动作或训练权限被改变。

系统参照至少包括单个3B、同骨干独立多采样加同一汇总器、全连图、空图、链、星、预固定随机图，以及14B参考。各参照固定模型版本、提示、采样数和评分权限，完整报告输入输出token与实际调用。14B参考同时呈现资源需求与质量成本位置。

### 恢复与敏感性

恢复实验预设A→B→A序列，冻结A与B的含义、转换位置、候选边空间、操作权限与诊断顺序。节点退化作为独立场景，预先固定施加方式及强度。全部阶段的质量、费用和恢复滞后均纳入结果。

恢复参考来自策略不可见的独立诊断，另列诊断成本和估计不确定性。主要指标包括分阶段服务质量、恢复后的质量差、检测与恢复滞后、误恢复与漏恢复，以及累计完整成本。

3轮敏感性沿用相同数据权限与预算口径，重新确认展开图、缓存闭包与真实资格。汇总器敏感性固定候选汇总器及其提示、容量和费用，重复关键主要比较。

### 主要指标、阶段门与交付

G4按任务报告质量与完整成本，并预先固定任务级汇总权重。GSM8K与BBH分别报告至少5个题流种子的结果，近邻和系统参照面对相同题流与评估规则。主要比较、区间、多重比较与恢复指标在生成前冻结。

进入封存评估前，冻结模型、预测器、角色、汇总器、λ、预算、阈值、任务scorer和分析代码。GSM8K官方test及已声明的BBH封存评估仅用于最终预声明分析，保留完整访问与评分记录。

G4门要求两任务、两项直接近邻、系统参照、恢复和敏感性均完整执行，主要预声明比较满足各自门槛，数据与成本审计通过。若效应仅在部分任务、预算或场景成立，最终结论按这些范围表述。

交付包括任务与评分清单、近邻能力和复现登记、多任务逐流汇总、恢复与敏感性结果、封存测试报告、可公开代码配置及可核对的聚合证据。

优势是同时检验任务范围、方法近邻和恢复机制。风险包括BBH评分与划分差异、近邻适配后的能力变化、多重比较、模型预训练对公开基准的潜在暴露，以及共享硬件对时间指标的影响。封存限制本项目的选择过程，预训练暴露另作局限说明。
