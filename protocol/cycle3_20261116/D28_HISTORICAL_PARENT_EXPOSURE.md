# D28 已有缓存的父题暴露核查

D27b 找到 100 个可形成四版本对照的父组。旧 D23 逐文件摘要登记中包含 HumanEval/test 文件。现在先核对所有该子目录登记项的字节摘要和行数，然后只投影 origin_query 与 prompt 字段。用 NFKC、大小写归一及词元空格规范化原版父题；如果历史提示包含完整规范化父题，记录这一父组在项目缓存内已经出现。按父组分区，污染传播到其语义变化与改写的所有后代。对未命中的组不授予独立资格，还要更广的暴露排查。

本检查仅判断项目历史覆盖，不评估模型训练暴露。不打开缓存得分，不检查候选生成或参考答案，不以近似相似度补配。全部 100 个组都命中时，只能将其列作探索性材料，不能替代新数据独立确认。
