# D18: cross-question realized-message decision foundation

EXPLORATORY development diagnostic after D16 source-state instability and D17 legal oracle headroom. No new generative model calls, independent data, formal candidate or GPU allocation. Maximum2 CPU wall-hours; two CPU threads. Do not reuse exposed questions as later confirmation.

Use the same192 question groups (96 per task), both source realizations and all4 terminal seeds. All copies of a question stay in the same fold, deterministic6-fold index modulo6. Train separately per task on5 folds, predict remaining fold. Targets are each source realization's mean EM over4 terminal seeds for ALL8 graph masks. No evaluation-question labels enter fitting, normalization or model selection. This is cross-question development evidence, not independent confirmation.

Fixed feature candidates: question embedding only; question plus the three actual source-message embeddings, source abstention flags, log text lengths, pairwise normalized exact agreement, message-message cosine and question-message cosine. All text is available before terminal generation, no terminal answer/logprob/gold/reference/source correctness feature. Local all-MiniLM-L6-v2, frozen weights, attention-mask mean pooling followed by L2 normalization, truncation256, CPU only. Hash all model/tokenizer/config files and record CPU wall time. Raw texts and embeddings remain private.

Fixed predictors: multioutput Ridge(alpha=10) for question-only and message features; ExtraTreesRegressor(n_estimators=128,min_samples_leaf=8,max_features=1.0,bootstrap=False,random_state=26111618,n_jobs=2) for message features. No hyperparameter search. Each output corresponds to one mask; embedding vectors retain unit normalization, only numeric message features use training-fold standardization. Clip predicted EM to[0,1]. Model choice is limited to the two named message predictors and disclosed as development selection; the SAME predictor must satisfy screens on both tasks.

Decision timing and accounting: all three source messages are generated BEFORE the administrative edge-removal shock, and are visible to the controller as archived pre-shock messages. The removed edge cannot deliver to M. Choose keep-current B or delete exactly one remaining edge; same D15 shock. Message-conditioned decisions PAY ALL THREE sources even if filtered or subsequently removed. Each source realization is a separate service trial; never average source realizations into a free ensemble. Use expected single-call service quality averaged over4 terminal seeds. Prediction chooses argmax(predicted EM-5e-6*known terminal input tokens); a common256 output-token cap and already-paid prefix cost cancel in selection. Actual evaluation charges all prefix and terminal input/output tokens. Terminal input counts are deterministic pre-generation quantities from verified requests, never output length as a decision feature.

Baselines: training-fold best fixed mask-priority policy (mask intersect current B, all8 priorities including empty), question-only Ridge with identical paid-prefix accounting AND stronger preselected nominal-prefix accounting, and matched-format no-note single terminal (graph0, no source generation). The preselected question-only policy subtracts TRAINING-FOLD mean nominal tokens per mask when choosing, because unseen source lengths are unavailable before generating sources. Fixed policy is selected only on training questions using actual nominal service utility. The no-note single control is a legitimate stronger alternative to generating unnecessary messages. Report original legal single-edit oracles with corrected all-prefix cost as upper-bound diagnostics, not policies.

Primary necessary foundation screen: at least one of the TWO fixed message predictors has mean utility gain>=.005 over EACH of training-selected fixed, question-only preselected, and matched no-note single on EACH task; gain must be positive in each source realization and in>=4 of6 question folds against each comparator. Report both candidates regardless of pass. No MSE gate; MSE is auxiliary only. Failure freezes these fixed message representations/predictors, not project. No repeated alpha/tree/feature search after seeing outcomes.

Secondary decision-risk diagnostic: negative predicted best-versus-second-best legal-action margin ranks risk. Report regret enrichment in the top24 of96 questions per source realization against the all-prefix paid legal oracle, aggregating by task; if total regret is zero report undefined. Necessary targeting screen is enrichment>=1.20 on both tasks for the SAME primary-passing predictor. This is not acquisition effectiveness: a later policy must acquire feedback on separate questions, pay labels/inference/repetitions, and beat random, periodic and uncertainty sampling under a new contract and fresh confirmation.

Report utility, EM, actual token cost, corrections/destructions, per-source and per-fold differences, eligibility counts, errors, hashes and full CPU execution time. No confidence intervals or confidence-interval bootstrap. Artificial fixtures and independent scalar replay are required before interpretation. Advantages: uses realized-state evidence, prevents question leakage, charges all observed messages. Risks: small exposed development sample, pretrained encoder may miss factual correctness, no feedback budget yet and token utility omits wall-latency valuation (reported separately). No predictor innovation claim.
