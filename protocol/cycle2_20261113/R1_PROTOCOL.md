# Cycle 2 R1：直接配对信用维护开发实验

本协议是新的正式候选轮，旧D2/D3失败不变。精确算子、数据、图模板、预算与门在 R1_PROTOCOL.json 冻结。
用 I 的旧图配对动作差选择 C 的复检边，复检仅影响随后独立 S 的单步编辑；不训练价值预测器。
8个互不重叠episode按4个节点循环置换×可编辑位互补平衡；I12/C12/S24，384正式题及6资格题。
唯一主比较为图变化后候选对均匀选边期望的S正确率差，k=2。8簇区间是开发描述，不是独立确认。
dirty只是启发式；汇总器可产生跨接收者交互，不能据局部性宣称旧信用精确不变。
主比较使用共同保守完整token/评分上限和相同反馈配额；实际费用单列，不声称实际花费相等或经济最优。
旧赢家的决策差距控制复检优先级；没有成本归一化消融，因为两轮单边增量闭包报价相同。
所有预生成菜单留在隐藏评估侧，每个随机副本或策略只获得自身购买格。S成绩不参与候选选择或增加样本。
若开发效果不满足固定投入规则，淘汰/暂缓该候选，继续R2等实质不同方案，项目状态保持ACTIVE。
资格及正式推理合计最多24GPU占用小时，属于160小时/5候选总上限。资格验证无效则修复而不宣称有效。
