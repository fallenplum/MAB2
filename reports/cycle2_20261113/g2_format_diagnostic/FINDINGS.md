# 主要判断

**格式错误存在，并与部分信用变化关联；现有证据不支持把它解释为G2信用稀疏或预测失败的单一主因。** 没有消息修复干预，本诊断不能做因果归因。

1. **稀疏性在完全格式正常的图对中仍然存在。** 本条均为逐题×seed×anchor×edge的单seed差。旧tune有9,600个配对、80题，单seed非零率6.96%。两张图全部9个节点格式均正常的6,317个配对、76题，单seed非零率仅5.16%，即94.84%仍为零；该子集占所有单seed零信用的67.07%。其中37.96%两侧均正确，56.88%两侧均错误。这些不是五seed聚合目标的稀疏率：旧tune的1,920个五seed均值credit中25.10%非零。零信用不能直接等同于通信无信息。

2. **被切换边的源消息失败与更稀疏信用只有弱的开发集关联。** tune源消息失败组438配对、31题，非零率5.02%，正常组7.05%；差−2.03个百分点，question-cluster探索区间[−4.56,+0.83]跨0。train相同方向，但不能把训练分区的关联当独立确认。受影响receiver至少一侧格式失败的tune组463配对、55题，非零率反而8.21%，与正常组6.90%的差值区间也跨0。

3. **未观察到传输裁剪，不应继续将其作为已证实根因。** 86,370个被引用唯一物理调用中，所有阶段message_trimmed均为0。r1有75/5,600个length结束；tune对应源length暴露仅60配对、8题，区间很宽，无法稳定归因。

4. **aggregate格式异常通常不等于原评分器无法解析数字。** 36,370个aggregate中3,310个格式异常，其中3,289个仍能由冻结raw评分器提取明确数字。全部aggregate数字可解析35,929/36,370（98.79%），这不是正确率。tune aggregate格式异常配对非零率13.72%，正常组6.03%；这是输出变化后的变量，与难度/输出不稳定性混杂，不能解释为异常导致收益。tune数字不可解析组只有1题，已取消其可推广区间展示并保留初版审计记录。

5. **原C2_R0的风险劣势在无aggregate格式异常的分层中仍存在。** 严格按原G2的10个跨seed误差乘积、每题24context再题均口径，旧tune全体B0风险0.00167921，C1_R0为0.00199524，C2_R0为0.00259322。无aggregate格式异常的1,081个context对原式全分区风险的贡献分别为B0 0.00025734、C2_R0 0.00080847。另列的经验五seed均值MSE是不同绝对指标（全tune B0为0.01526254；噪声项0.01358333），不可与旧heldout主风险混比。所有预定模型与分层均保留，未重选模型；上述描述性结果仍不能识别因果。

   **尺度差不能解释G2模型比较失败。** 固定预测满足cross-seed risk=(pred−mean(d))²−samplevar(d)/5；扣项与模型和alpha无关，同完整5seed cell及权重下MSE差与原风险差相同，调参排名不会因换这两个口径而改变。分层风险保留全题/24context分母求贡献，暴露+未暴露严格加回原风险；条件子集不被宣称为新的无偏风险。

6. **exact-cache仅得到狭义候选线索。** 配对受影响receiver两侧都触发固定fallback的子集，train353配对/78题、tune69配对/24题，观察到非零信用均为0。cache只记录三固定字段语义一致，未保留逐对wire字节或aggregate输入/输出hash，因此没有建立一般性零effect证书。后续若研究精确缓存，所有baseline必须共用同一规则。

优势是单次读取原始执行、逐文件SHA绑定、145,480个真实receiver输入列表核对，以及33,600个新增消息token差检查；没有依赖资格6题的错误率作推断。风险是旧train/tune已被历史开发使用，输出异常分层可能有选择偏差，且缺乏修复消息后的反事实。

置信度：记录与数值核对高；方向性关联限于本开发集；关于“格式失败导致G2失败”的因果判断没有足够证据。资源为一次885.99MB原始扫描、约16.52分钟本地I/O与CPU，新增GPU为0，不消耗正式候选轮。
