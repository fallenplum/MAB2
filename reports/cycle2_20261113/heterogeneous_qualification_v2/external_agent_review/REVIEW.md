低层 tokenizer 复算没有导入生产执行器，也没有重放原服务器的 Transformers chat-template 和模型生成。完整 prompt token 数、生成 token 数与物理日志逐条一致，但原始 token ID 未保存在这些产物中，故该部分属于记录交叉核验；不声称本地软件环境与原后端完全等价。

**发现 F2：生成前拒绝与生成内失败的记录形式不同（未来故障处理边界）。**

`HFBackend.generate` 的 chat-template、8192 输入上限和模型位置上限检查位于生成 `call_id` 及物理日志 `try/_record` 之前。这类拒绝会在路由层留下 `FAILED` 事件，并由 resident 账本记录整体占用，但不会产生对应的 HF 物理失败行；路由失败行也不含 token 数和耗时。已有 64 次调用全部成功，因此不影响本次实际账本闭合。未来真实长输入若触发此路径，审计应区分“生成前拒绝”与“生成内失败”，不得把缺失数值当作 0，也不能无条件要求失败路由与物理日志一一对应。本次未故障注入或新增推理。

**对后续真实任务的适用判断**

优势：真实两模型后端已完成固定节点调度，消息预算方向经独立 tokenizer 计数确认，缓存保守失效和完整逻辑成本保留得到实际重放支持。将此实现作为后续有独立冻结协议的真实任务执行基础，工程依据充分；该限定判断置信度高。

劣势与风险：证据仅覆盖两个人工任务、一个种子、一个固定模型路由、三轮图和一次边删除。未覆盖真实输入装载、长上下文边界、真实评分器、较长持续负载、失败恢复或异构模型质量。发送方 128-token 上限只约束该发送 tokenizer 的 wire；接收同一字符串可能更多或更少 tokens，接收端的最终约束是完整 prompt 上限。跨模型同名 token 数也不自动代表相同信息量或算力成本。

后续真实任务可执行性属于**有条件支持，置信度中**：需要其输入/schema、完整上下文预算、失败分母、评分链、冻结模型路由和完整资源预算分别通过对应检查。不能由本次 synthetic 输出正常推出“真实任务质量已通过”或“异构优于同构”。两个 synthetic 任务未见格式错误，不足以估计真实任务格式错误率；本报告不计算或引用 synthetic 准确率。
