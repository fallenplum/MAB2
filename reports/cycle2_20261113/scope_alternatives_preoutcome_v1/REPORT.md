# 静态 B 之外：图条件信用维护的两个有界问题

2026-11-13；当前 Hotpot 结果开放前的一次外循环分析。未读当前题目、输出、标签或中间质量；无新模型调用、无 GPU，无新准入、无合同修改。本文只给问题和排除边界，不把任何候选宣布为新算法。

**结论：若静态 B 最终未通过 no-edge 比较，只能执行原合同对该 B、该算子和该总体的判定，不能扩写为项目级封锁。反过来，它也没有给其他图或条件维护提供正面证据。最多保留两个条件性问题：完整信息下的“中央方案之外是否还有维护价值”，以及有来源证明的信息分布约束下的“通信图是否值得维护”。目前二者都缺少关键前提，均不具备直接进入新正式轮次的理由。** 当前正式 Hotpot 尚未读取成绩；本文所有关于 B 失败的讨论均为条件命题。

## 1. 从第一性原理分开三个量

设 z 是决策前合法可见的任务条件，g 是背景图，e 是一条待留/删的边。固定模型、提示、解码和信息权限下，边的存在信用是 τ_e(g,z)=E[Y(g+e)−Y(g−e)|z]。这些符号只是解释对象，不修改现有 θ、风险门、边集或统计合同。

| 问题 | 必须证明什么 | 不能代替它的现象 |
|---|---|---|
| 条件路由价值 | 一个事先可执行的 z→动作规则，在独立未来题上优于适当固定/中央参照 | 事后按哪种方法答对来分组；逐题 oracle 选对答案 |
| 图条件信用价值 | 同一决策相关边的作用随 g 变化，足以改变有代价的留/删动作 | 仅有字符串变化、无符号差异、显著方差或 θ 正点估计 |
| 信用维护价值 | 付费修正旧信息后，有限服务时段中的收益超过不维护、直接重学和通用验证 | 估计 MSE 较小、旧银行上排序较好、无限摊销后的节约 |

“未显著胜过”也不等于“严格被支配”。即便总体真均值 E[Y_B−Y_no-edge]≤0，也不蕴含每个 z 的条件差都≤0。人工精确反例：两个条件等权，no-edge 正确率分别 0.80/0.60，B 为 0.65/0.70；静态均值 0.675<0.700，但按条件只在第二类用 B 得到 0.750。再加入中央方案 0.80/0.75，其均值 0.775 又击败这个图路由。**因此“存在交互”“条件选图可改善”“图优于中央方案”是三件不同的事。** 本例是构造，不是实测；配套 `logic_checks.py` 用有理数核验。

共享完整输入的图不会因此获得额外外部信息。充分灵活的中央控制器原则上能编排同样的调用和消息程序；这不意味着单次中央 LLM 在相同时间/内存下总能模拟它，而是说明此时应研究有限算力下的计算组织、归纳偏置或并行性，不能声称信息必须分散。中央基线不能被人为禁止使用与候选同样可得的任务条件、历史和更新机会。

## 2. 共同的最少必要条件

1. **动作有空间。** 至少有一个合法非平凡动作，在明确总体/条件下存在质量—费用改进空间；同一最优动作处处不变时，无需学习条件信用。未测到空间只是不确定，不能据此发明一个更强 proxy。
2. **变化有决策意义。** 背景图变化确实使旧留/删动作失效，且是实际任务/外部可用性变化，或明确声明的受控压力情景；不能为制造收益而频繁主动扰动图。
3. **信息可获得且可泛化。** 路由条件在动作前可见，新增反馈按共同权限购买；错误不能由同一份已曝光银行中的事后条件或 gold 预测出来。若只在选择集有效，维护主张失败。
4. **中央对照可比。** 完整信息任务必须允许中央完整信息；分布式任务必须保留同权限、同获取费用的中央调度/聚合，及完整信息中央诊断参考。最后一个若现实不可行须明确标为参考，不能装成公平可部署方案。
5. **服务时段有限。** H 及任务到达/变化率来自独立应用约束，或事前固定的情景；不能见结果后把 H 拉长。没有可信 H，只能研究机制，不能声称维护有实际净价值。
6. **能承担完整验证。** I/C/S 的角色、同题/同 episode 依赖、完整成本和最小值得检测的改进事前确定。小样本区间宽时保留“不确定”，不能把支持数阈值当覆盖定理。

已有 R1 change/k2、R2 β=1 paired residual、R3 gap_bundle 的失败原判保留。literal r1 分歧×receiver 变化筛查的 tune 13/37 支持不足，停止该 proxy；本文不换 normalizer、条件或分歧定义再扫同一银行。上述失败和支持数依父任务及已归档汇总引用，本轮未重读结果数组。历史 E6 的记忆仅提醒“试探费用会吞掉表面收益、硬 cap 与期望费用不同”；未将未重验的旧数值作为新证据。

## 3. 问题一：完整信息下，图条件维护是否超出普通条件路由

**可证伪问题：** 在一个有事先存在的任务条件与外部变化时点的服务场景里，维护少量固定图的边信用，能否在给定 H 和完整预算内，胜过拥有相同完整输入、历史、更新权限的中央条件路由/重估？

这是“增量维护价值是否存在”的问题，不是重新提出任务条件图生成。条件只能来自原服务流程已有的元数据或事前冻结的可计算输入；本轮没有找到并验证一个满足该条件的具体服务来源。若需要新 LLM/judge 推断条件，该费用须计入且所有对照享有同样信息。不得把刚失败的字面分歧 proxy 换名重新搜索，也不得从当前 Hotpot 哪类答得好反推条件。

**最低低成本排除检查。** 首先只查来源说明、算子和费用几何：条件是否在服务决策前存在、是否有独立支持、背景变化是否真实、中央同信息方案能否直接取得所需信息、H 是否有来源。任一项缺失便暂停此问题的实验申请。通过后才可另提一次新开发小筛查：固定至多两种事前定义条件，不训练更强预测器，不搜更多图，查看简单条件表是否还有超出中央参照的空间。历史银行和当前封闭结果不用于该筛查。训练集上经验逐题 oracle 的好看结果不是可部署规则，更不是所有策略的严格上界；只有对明确固定动作/信息类、已知真实条件均值的 oracle 才有相应数学界。

**独立实验权限与强基线。** 未来若立新合同，用互不重叠的 I（初始信息）、C（可购买的变化后反馈）、S（只评估未来服务）和外生变化 episode。至少比较：不更新的最优固定方案；使用同 z 的中央路由；允许重新估计的中央路由；无 peer 边的独立多样本聚合；固定图/一次剪枝；同停止和弃权权限的随机或周期复检；旧信用仅作排序、使用相同新鲜验证器的受限维护。RouteLLM/UniScale 是中央路由近邻，G-Designer/GTD 是条件图近邻；受限统一实现必须标为适配，不能冒称原论文完整复现。基线可选择不买反馈，不能强迫用完候选节省的预算。

I 若是所有方案实际已经服务并支付的共同状态，可共同使用；若为候选专门生成，不得让单模型中央基线替它支付。共同 exact-cache 只省真实重复调用，不给政策未购买的反馈。比较同时保留全冷启动与真实已有状态口径，不能仅靠删去初始化成本解救失败路线。

**正结果边界。** 必须在独立 S/episode 上支持两项不同结论：固定的新反馈过程纠正了图变化导致的旧动作错误；包含全部学习、路由、反馈和服务费用后，维护相对预定中央/直接重学参照达到事前最小有用改进。先验/训练折拟合收益、C 上更低风险、显著交互只能算机制证据。若采用质量约束，约束来自服务要求，不能照结果设置；若无合法资源换算，报告质量与各模型资源向量，不将 EM 与 token 相减。

**负结果与放弃。** 独立比较的区间上界低于预定最小有用增益，可排除该场景、动作类、H 下的有用维护；若符号交互不存在且留/删动作不变，放弃该信用目标。仅未显著为正而区间宽时记不确定，不换条件重跑。若中央更新匹配或击败候选，只保留普通条件路由/工程组织结论，放弃图维护的独立价值主张；若仅胜静态弱基线，同样不通过。

**成本可行范围，非分配。** CPU 来源/代数检查是 0 新调用。仅为量级核算：沿用固定 13-call 算子，单次中央 Q/M、独立12+aggregate、no-edge、B 合计每题 41 个完整逻辑 calls；64–128 个新开发题、一 seed 是 2,624–5,248 calls。它仅适合排除巨大缺陷，不能确认 2pp 等小效应或信用漂移。若另研究两个固定背景 A/B，则六个基础配置明确为 single-Q、single-M、independent12、no-edge、A、B，共1+1+13+13+13+13=54 calls（B 已在41内，只新增A的13）。再加 A−e/B−e 两配置26 calls，每题80；第二 seed 只重做四个信用配置又加52，即132 calls/题，64–128题为8,448–16,896。此处 A/B 仅标识预先固定的费用几何，不重新分析当前 A/B 输出。全部试探、失败和后续独立确认继续计费。这些不是 GPUh 预测；必须以该新输入实际驻留、装载和 scorer 费用另做封顶，不得占用当前已保留预算或假定并行 wall 等于 GPU 总时。若余量不能同时容纳必要基线和确认，放弃本轮提名，不能删中央基线来凑预算。

优势：能明确区分条件路由收益和图信用增量，允许得到有用负结论。风险：新问题与已有路由高度重叠，且条件细分可能使支持进一步稀疏。**当前状态 DEFERRED：缺可信服务条件/变化/H 和独立头部空间证据；新颖性低，经验收益置信度低。**

## 4. 问题二：来源真实分散时，维护通信图是否在部署结束前回本

**可证伪问题：** 若独立应用事实已经造成信息/工具访问分散，且获取或传输有可测代价，当来源可用性或可靠性发生外生变化后，旧通信图信用的少量付费复检，能否在有限 H 内优于固定合法通信以及中央付费汇集？

信息约束须在设计候选前有来源：独立控制的工具/数据所有者、实际地理链路成本、不可忽略的传输或时延限制等。法律或隐私限制不能只写一句“数据私有”，还须说明谁能合法获取何种原文、摘要及反馈；本报告不作法律判断。不允许把当前本来完整共享的 Hotpot 上下文人为切片，然后拿“局部 no-edge 答不好”证明部署通信必要。受控分片可以是明确标注的机制玩具，不能据其成功申请真实部署或维护收益主张。

**最低低成本排除检查。** 0 GPU 完成一份来源/权限/传输账表，并由实际来源独立证明。用 CPU 人工任务检验可识别性：存在相同本地观察而其他来源事实不同、要求答案/动作不同的任务对。这可证明该构造在局部信息下不能总成功，不能证明真实任务出现频率或图维护优于中央汇集。再算一个中央发送原始必要信息或固定摘要的合法路径：若费用/时延足够低且无实际限制，放弃“分布式信息必须导致图维护”的动机。此轮未发现或认证符合要求的真实来源，故检查停在来源缺证，不新采集数据。

**独立实验权限与强基线。** 将“信息来源变化 episode”作为单位，预先固定外生变化过程和 H；I/C/S 与当前项目数据隔离。比较本地 no-edge；同权限的中央调度/聚合（允许按需询问、重复询问、停/弃权）；合法的一次原文汇集或固定摘要；静态图及不维护；同新鲜反馈预算的直接重学/随机周期复检；信用维护。完整信息中央解作为诊断参考（不是有最优性保证的性能上界），若实际可行就必须升级为正式强基线。局部 summary、请求/回复、反馈质量验证、重传/失败、中央处理和模型加载均计费；中央访问受限时，图候选也不能经消息偷看受限原文。

**正结果边界。** 至少分开证明：(a) 合法跨源信息确实提高任务可解性/质量，相对局部 no-edge；(b) 在同权限下，维护相对中央付费汇集和静态/通用复检具有有限 H 的增量净价值。仅(a)成立不能宣称(b)。如果集中方案不可部署，正结果只限明确约束下的通信维护；不声称无约束优于中央推理。图动作改变须由旧信用失效引起，不是每次任务内容变化重新生成任意图。

**负结果与放弃。** 没有真实来源约束、对照被禁止接收其本可获得的信息、只有研究者制造的碎片化、或中央汇集更好且合法，立即放弃此实例。来源确实分散但固定 star/按需中央询问已经达到同预算效果，则保留通信必要性、放弃信用维护的增量主张。若到外部规定的 H 结束仍不能抵偿维护成本，不延长 H；若区间太宽则记不确定，不换传输惩罚制造胜利。

**成本可行范围，非分配。** 当前可授权内容仅来源审计和人工 CPU，不需模型。若未来来源成立，先限 2–4 个真实站点和一个固定变化家族，避免工具、模型、任务大矩阵。仅在每个固定配置能被13-call上界覆盖时，4个基础配置×64–128 episodes为3,328–6,656完整逻辑calls；否则该范围不适用。它没有包含信用学习/复检和独立确认，不能作为总预算。网络、CPU、token、驻留分别计，不能用另一个任务的秒/call换算成可靠GPUh。本轮没有可据以申请预算的总费用上界。

优势：如来源事实成立，问题有清晰部署含义；可将信息必要性与维护价值分开证伪。风险：最容易通过人为隐藏共享输入制造优势，也容易将普通按需检索包装成图研究。**当前状态 DEFERRED_SOURCE_EVIDENCE：具体部署约束、来源变化频率及有限 H 均缺证据；不是当前失败路线的替代数据集准入。**

## 5. 有限 H 的最低算术，不是新算法

在相同质量约束确已成立、只比较一个事前固定成本单位时，令 K 是维护相对参照的新增初始化/反馈/切换成本，s 是扣除每题路由/监测后每次服务净节约。常量近似下，ΔC(H)=K−Hs；s≤0 无法靠该维度摊销，s>0 的严格节约要求 H>K/s。若服务代价或变化时点不恒定，须用实际 Σ_t s_t，不套常数比率。K 若已是各方法共同真实沉没成本可以抵消；候选新增成本不能假装沉没。品质不同或资源是多维向量时，该式不能直接证明总体收益。

人工例 K=1000、s=2，只在 H>500 后该成本维度才严格节约；H=500只是打平。H=100时成本仍多800。它不是本项目测量，也不含准确率价值。完整研究预算还需纳入所有对照生成和封闭评估；这些 evaluator-only 数据不自动成为任何服务策略的信息。

固定 cap、实际花费和同调用数是不同比较。各方案共享合法缓存和停/弃权权利；只报告每单位已买反馈的信息效率会漏掉买反馈的必要性。HT/Neyman、条件 bandit、AIPW、VOI、aLTT、通用停止规则均为既有方法，不是上述两个问题的原创技术。

以上所有未来量级仍受既有累计 160 GPUh/5 正式候选总约束，不是新增额度。本轮没有读取实时消耗/保留账本，不声称现有剩余资源足够；本任务实际费用只有 CPU/检索，新增 GPU 为 0。
